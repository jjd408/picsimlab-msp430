# MSP430 support for PICSimLab

This copy of PICSimLab 0.9.3 adds a simulation backend for the TI MSP430FR2355, so the solitaire handheld's
firmware can run in PICSimLab. Your original source in `~/picsimlab-0.9.3` and the installed
`/usr/bin/picsimlab` are untouched.

## Running it

```sh
./run.sh                                          # start PICSimLab, then Board > MSP430 Board
./run.sh MSP430_Board MSP430FR2355 firmware.hex   # start straight into a board and firmware
```

`run.sh` builds PICSimLab, puts the binary in `run/bin`, and runs it with `run/home` as its home folder, so its
settings (`~/.picsimlab`) are kept apart from the installed copy's. Use **File > Load Hex** for firmware built
with `msp430-elf-gcc -mmcu=msp430fr2355` and converted with `msp430-elf-objcopy -O ihex`. The hardware
multiplier is modeled, so the default `-mhwmult` is fine.

The **Clk (MHz)** setting is the simulation's time resolution, not the CPU speed: the chip runs its own MCLK,
and each simulation step is 1 / Clk seconds. Keep it at or above the fastest pin activity you care about.

## How it's built

| Part | File | What it does |
| --- | --- | --- |
| CPU core | `src/sim_backend/msp430/msp430_cpu.c` | MSP430X instruction set, taken from MSPDebug's simulator (GPL v2+). Memory accesses go through the chip's bus at their real width. |
| Chip | `src/sim_backend/msp430/fr2355.cc` | FR2355 memory map, peripherals, interrupts, pins (TSSOP-38). |
| Timer_B | `src/sim_backend/msp430/timer_b.cc` | The four Timer_B instances; jumps between compare events rather than counting each tick. |
| eUSCI_B | `src/sim_backend/msp430/eusci_b.cc` | UCB0 and UCB1 as SPI masters. |
| Backend | `src/sim_backend/bsim_msp430.cc` | Connects the chip to PICSimLab: pins, stepping, hex load/save. |
| Board | `src/boards/board_MSP430_Board.cc` | A bare board (from uCboard) with power, reset and the chip. |

### Fixed from MSPDebug

- On the MSP430X CPU, MSPDebug's `RETI` falls through into the `CALLA` code (a missing `break`), so every return
  from an interrupt pushed four stray bytes.
- Its MSP430X timing charged a memory read for constant-generator operands (`#0`, `#1`, `#2`, `#4`, `#8`, `#-1`),
  so `inc`, `dec`, `clr`, `sbc` and `push #0` took an extra cycle and `__delay_cycles` ran about 50% long.

## What's modeled

| Peripheral | Status |
| --- | --- |
| CPU (MSP430X), RAM 4 KB, FRAM 32 KB, info FRAM | Done. FRAM write protection (SYSCFG0 PFWP/DFWP) is honoured. |
| Reset: BOR, PUC, RST pin, SYSRSTIV | Done for power-on, RST pin, watchdog time-out and password violations, PMM software BOR/POR. |
| LOCKLPM5 | Done: pins stay high-impedance until firmware clears it, as on the chip. |
| Ports P1–P5 | Done: IN/OUT/DIR/REN (pull-ups and pull-downs), interrupts on P1–P4 with PxIES edge select and PxIV. |
| Watchdog | Done: watchdog and interval modes, SMCLK/ACLK/VLO, all intervals. |
| Low-power modes LPM0–LPM4 | Done: the CPU stops until an interrupt; SCG1 (LPM2–4) stops SMCLK, OSCOFF (LPM4) stops ACLK; SCG0 freezes the FLL. |
| Clock system (CS) | Done: FLL (FLLN, FLLD, FLLREFDIV, DCORSEL range, unlock flags), MCLK/SMCLK sources and dividers, ACLK from REFO or VLO. The board has no crystal, so asking for XT1 sets XT1OFFG and falls back to REFO, as the chip does. The FLL locks instantly, and DCO trim (CSCTL0) isn't modeled. Running above 8 MHz without an FRAM wait state (NWAITS) prints a warning. |
| LPM3.5/LPM4.5 | Done: PMMREGOFF + LPM3/LPM4 powers the core down with pins held; a P1–P4 interrupt edge wakes it through a reset (SYSRSTIV 0x08, PMMIFG.PMMLPM5IFG); RAM is lost; pins stay held until LOCKLPM5 is cleared. The RTC isn't modeled, so it can't wake the chip. |
| PMM / FRCTL passwords | Done, including unlocking with a byte write to the high byte, as TI's code does. |
| Hardware multiplier (MPY32) | Done: MPY, MPYS, MAC, MACS in 16- and 32-bit operand widths, SUMEXT, carry. Saturation and fractional modes aren't modeled (msp430-gcc doesn't use them). |
| Timer_B0–B3 | Done: up, continuous and up/down modes; 16/12/10/8-bit lengths; ACLK or SMCLK with ID and TBIDEX dividers; all eight output modes on TB0.1/2 (P1.6/7), TB1.1/2 (P2.0/1) and TB2.1/2 (P5.0/1); the CLLD compare latch; capture from those pins or by software; CCR0 and TBxIV interrupts. TB3's pins are on port 6, absent from the TSSOP-38, so it only runs internally. Not modeled: TBxCLK/INCLK sources, TBCLGRP grouping, synchronized capture, internal CCIxB inputs. |
| eUSCI_B0/B1 SPI | Done for master mode: ACLK or SMCLK with UCBRx; clock phase and polarity; MSB or LSB first; 7- or 8-bit; TX buffer and shift register, RX buffer and overrun; UCBUSY; loopback; 4-pin STE output (UCSTEM); UCTXIFG/UCRXIFG and UCBxIV. Pins: UCB0 on P1.0–P1.3, UCB1 on P4.4–P4.7 (PxSEL = 01). Each clock edge reaches the pins in its own simulation tick, with STE set up a tick before the first edge and held a tick after the last; a bit clock faster than half the Clk setting slows to it, with a warning. Not modeled: slave mode, I2C, the eUSCI_A modules. |

Instruction timing comes from MSPDebug's cycle counts and is approximate. Peripherals behave as the
FR4xx/FR2xx family user's guide (SLAU445) describes; they haven't been checked against real silicon.

## Tests

`src/sim_backend/msp430/tests/run_tests.sh` builds test firmware with msp430-gcc, runs it on the chip model
without the GUI (`msp430_run`), and checks the results:

- `step1.c`: arithmetic self-check, a P1.1 falling-edge interrupt waking the CPU from LPM3 (through the pull-up),
  the watchdog's interval interrupt on ACLK, and P1.0 toggling.
- `wdtreset.c`: a watchdog that's never stopped resets the chip every 32768 SMCLK cycles; SYSRSTIV reports it.
- `mpy.c`: 8- to 64-bit multiplies, built with the hardware multiplier and without; both must match values
  worked out on a PC.
- `clocks.c`: the DCO at 8 MHz through the FLL as TI's examples do it, SMCLK divider, instruction timing
  (`__delay_cycles`), SMCLK stopping in LPM3.
- `lpm45.c`: LPM4.5 with a pin held, waking on a pin edge through a reset.
- `timers.c`: EXTCOMIN as the handheld will make it (TB2.1 on P5.0 at 60 Hz from ACLK, also while in LPM3),
  PWM, CCR0 and TBxIV interrupts, pin capture. `updown.c`: up/down mode with the compare latch.
- `spi.c`: UCB1 as SPI master, polled, in loopback and from its interrupt; the runner decodes the bytes on the
  pins as a device would (`--spi`), in mode 0 MSB-first (the display's) and mode 3 LSB-first, at two Clk settings.

`tests/gui_smoke.sh firmware.hex info pins` runs firmware in the real PICSimLab, sends remote-control commands
and closes it cleanly. PICSimLab takes about 15 seconds to start here.

## Building

PICSimLab's makefile doesn't track header dependencies; `src/Makefile.Common` adds them for the MSP430 code, so
changing a header in `sim_backend/msp430/` rebuilds everything that includes it. (Before that rule, a stale
object allocated the chip model at its old size and corrupted the heap.)
